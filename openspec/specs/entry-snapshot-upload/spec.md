### Requirement: Write entry snapshot to S3
The `EntryFileStorage` port SHALL expose `WriteSnapshot(ctx context.Context, entry domain.Entry, snapshotID uuid.UUID) error`. The S3 adapter SHALL serialize the entry as JSON and store it at key `entries/<snapshotID>.json` in the configured bucket. The `snapshotID` is generated by the caller (service layer) as a new random UUID — the adapter never generates it.

#### Scenario: Successful write
- **WHEN** `WriteSnapshot` is called with a valid `domain.Entry` and a `snapshotID`
- **THEN** the adapter SHALL call S3 `PutObject` with key `entries/<snapshotID>.json`, content type `application/json`, and the JSON-serialized entry as the body

#### Scenario: S3 write error propagation
- **WHEN** the S3 `PutObject` call returns an error
- **THEN** `WriteSnapshot` SHALL return that error unwrapped, without swallowing it

#### Scenario: S3 write before transaction
- **WHEN** `CreateEntry` is called with valid input
- **THEN** `EntryFileStorage.WriteSnapshot` SHALL be called before `txManager.RunInTx`

#### Scenario: S3 failure prevents DB write
- **WHEN** `EntryFileStorage.WriteSnapshot` returns an error
- **THEN** `CreateEntry` SHALL return that error and no entry or outbox row SHALL be inserted

#### Scenario: DB failure after S3 success leaves orphaned file
- **WHEN** S3 write succeeds but the DB transaction fails
- **THEN** the S3 file SHALL remain (orphaned) and `CreateEntry` SHALL return the DB error

### Requirement: Read entry snapshot from S3
The `EntryFileStorage` port SHALL also expose `ReadSnapshot(ctx context.Context, snapshotID uuid.UUID) (domain.Entry, error)`. The S3 adapter SHALL fetch the file at `entries/<snapshotID>.json` and deserialize it into a `domain.Entry`.

#### Scenario: Successful read
- **WHEN** `ReadSnapshot` is called with a valid snapshot UUID
- **THEN** the adapter SHALL call S3 `GetObject` with key `entries/<snapshotID>.json` and return the deserialized `domain.Entry`

#### Scenario: S3 read error propagation
- **WHEN** the S3 `GetObject` call returns an error
- **THEN** `ReadSnapshot` SHALL return that error unwrapped, without swallowing it

### Requirement: Each event generates an independent snapshot with a random UUID
Every status transition (created → processing → published) generates its own S3 file. The snapshot ID is a new `uuid.New()` generated at write time by the service layer. Files are flat under `entries/` — no subdirectories.

S3 key format: `entries/<snapshotID>.json`

The snapshot ID is propagated forward via `file.name` in the event payload so the next step knows what to read. Example lifecycle:
- Entry created → `entries/<uuid1>.json` — ID stored in outbox `event_data.file.name`
- Entry processing → `entries/<uuid2>.json` — ID stored in SQS message `file.name`
- Entry published → `entries/<uuid3>.json` — ID stored in outbox `event_data.file.name`

#### Scenario: Three independent snapshot files after full lifecycle
- **WHEN** an entry completes the full lifecycle (created → processing → published)
- **THEN** three independent files SHALL exist in S3: `entries/<uuid1>.json`, `entries/<uuid2>.json`, `entries/<uuid3>.json`
- **AND** each file SHALL have a different snapshot UUID in its path
- **AND** each file SHALL reflect the entry status at the moment it was written

### Requirement: LocalStack endpoint override
The S3 adapter SHALL support a configurable endpoint URL to allow local development against LocalStack.

#### Scenario: LocalStack endpoint override
- **WHEN** `S3Endpoint` is set in config (non-empty)
- **THEN** the S3 client SHALL use that endpoint URL instead of the default AWS endpoint

#### Scenario: Production endpoint (no override)
- **WHEN** `S3Endpoint` is empty in config
- **THEN** the S3 client SHALL use the default AWS endpoint resolver
